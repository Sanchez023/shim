# Changelog

All notable changes to OpenHarness should be recorded in this file.

The format is based on Keep a Changelog, and this project currently tracks changes in a lightweight, repository-oriented way.

## [Unreleased]

### Security

- **An enabled sandbox no longer degrades silently to the host.** `sandbox.enabled = true` with an unreachable runtime used to fall back to unsandboxed execution unless `fail_if_unavailable` was also set. The new `sandbox.unavailable_policy` (`deny` by default, `warn` to opt into the old behaviour) makes the fallback an explicit choice; `fail_if_unavailable` is kept as an alias. See ADR-0012 D5.
- **Plan mode asks instead of refusing when a command cannot be classified.** `is_read_only_command` collapsed "this mutates" and "I cannot tell" into one `False`, and plan mode turned both into an unanswerable deny — `wc -l $(find …)`, `find … | xargs wc -l` and `find … -exec …` were dead ends even though they only read. The classifier now returns `read_only` / `mutating` / `unknown` (`command_safety.classify_command`), and plan mode refuses `mutating` while asking for `unknown`. Headless callers without an approval callback still fail closed. See ADR-0013.
- **A grep pattern is no longer read as a credential path.** `_path_token_is_sensitive` normalised every backslash to `/`, so the regex `environ\|shadow\|\.ssh\|netrc` became `…/.ssh/…` and matched `*/.ssh/*` — a hard deny for a read-only command. Separators are now normalised only for native Windows absolute/UNC paths, and the first positional argument of `grep`/`rg`/`sed`/`awk` is treated as a pattern rather than a path. See ADR-0013 D4.

- **Removed four hardcoded provider API keys from the test suite.** `tests/test_untested_features.py`, `tests/test_real_large_tasks.py`, `tests/test_merged_prs_on_autoagent.py` and `tests/test_hooks_skills_plugins_real.py` embedded a live `sk-…` key as a fallback; all four files are deleted (they were pinned to a developer's home directory and two of them collected zero tests). A new `tests/test_no_committed_secrets.py` scans every tracked file and fails CI on a credential-shaped string. **The key must also be revoked and purged from git history — deleting it here is not enough.**
- **Read-only command classification now parses argv instead of raw text.** `is_read_only_command` resolved option *names* (clusters like `-ro`, glued values like `-oFILE`, and GNU long-option prefixes like `--out=`) against a per-command table of write-capable flags, so `sort -ro out.txt`, `tree -ao …`, `fd -HIx …`, `uniq - out.txt` and `sort --out=x` no longer run without confirmation in plan/default mode.
- **Credential-path matching expands globs before deciding.** `_is_sensitive_path` previously matched the literal token text, so `cat .[s]sh/id_rsa` was classified read-only and the shell expanded it afterwards. Patterns are now expanded (bounded) and each match is checked; brace expansion and matches beyond the bound are treated as unresolvable and require confirmation. `~/.openharness/settings.json`, session files, `~/.netrc`, `~/.pypirc`, `~/.npmrc` and `~/.config/gh/*` joined the always-denied list, closing a persistent privilege-escalation path.
- **The `config` tool is no longer a privilege-escalation or secret-leak path.** `set` is restricted to an allowlist of cosmetic settings (`theme`, `output_style`, `effort`, …); `permission.*`, `sandbox.*`, `hooks.*`, `mcp_servers.*`, `api_key`, `base_url` and `profiles.*` are refused. `show` masks values under secret-looking keys. `settings.json` is now written with mode `0600` like `credentials.json`.

### Fixed

- **A finished answer is no longer folded behind "… N more lines".** Every assistant message was clamped to `max(8, rows − 12)` rows — including rows already printed into scrollback — and the newest items never left the live frame, so the reply you had just received could only be read through `ctrl+o`. A completed turn's tail is now flushed into `<Static>` and scrollback rows render unclamped; only the live frame (streaming output, in-progress tools) still folds. The misleading `(esc closes)` suffix is gone; the transcript panel keeps closing with esc/q/ctrl+o.

- **Checklist items are no longer left open by a reworded status update.** `todo_write` matched items on exact text (case/whitespace-insensitive), so a model that restated an item — `起草 ADR-0012` → `起草 ADR-0012 与 0013` — appended a *new* ticked line and left the original unchecked forever. Matching now ignores separators entirely, and a near-miss restatement flips the existing line instead of appending (numbers are treated as meaningful, so `ADR-0012` and `ADR-0013` stay distinct). The tool result also reports what is still open (`2 still open: "…"`) and whether everything is done, so the model can see the leftovers; the permission-mode prompt block gained a matching checklist-hygiene rule.

- **A tool call cut off by `max_tokens` is no longer executed.** The truncation handler emitted a status warning and then dispatched the tool anyway, so a `write_file` whose arguments happened to survive truncation as valid JSON wrote a half-finished file. Truncated calls now get `is_error=True, "Not executed: …"` results that keep the tool_use/tool_result pairing valid, and nothing touches the workspace. See ADR-0012 D1.
- **A stream without a completion signal is reported, not passed off as finished.** When no adapter saw `message_stop` / `[DONE]` / a non-null `finish_reason`, the reply was persisted as a normal answer. It now emits a status warning and the "turn complete" event is emitted after the caveat, so an unprovable completion is never the last word. See ADR-0012 D2.
- **Cancellation, approval prompts and MCP calls can no longer wedge a turn.** A cancelled tool in a parallel batch was converted into an `is_error` tool_result and the remaining tools kept running; an unanswered approval prompt waited forever; an MCP server that never replied hung the step. Cancellation now propagates, the approval gate expires (600 s, treated as refusal), and MCP tool calls time out after 300 s. See ADR-0012 D3.
- **`_path_is_within` no longer raises `NameError`.** The helper used `Path` without importing `pathlib`, so writing outside the workspace in default mode crashed while building the "outside the workspace" explanation.
- **Session snapshots are written session-first, then `latest.json`.** The pointer was written before the session file, so a crash in between left `latest.json` dangling. See ADR-0012 D7.

- The React TUI prompt disappeared after a long agent turn. The live conversation area used `flexGrow` without an upper bound, so a tall tail (many messages, long tool output, or one very long wrapped line) grew the live frame past the terminal height and pushed the input and status bar off screen. The conversation row now has a fixed flex basis and `overflowY="hidden"`, each message is clamped by **wrapped** rows rather than logical newlines, and `ConversationView` renders only the newest groups that fit its row budget (`selectVisibleGroups`). Older content remains in Ink's scrollback and the full text stays available via `ctrl+o`.
- **A `stop` hook with `block_on_failure` could not block anything.** `StepRunner` awaited `hook_executor.execute(HookEvent.STOP, …)` and discarded the aggregate, so the verdict never reached the loop. The blocked result now feeds the completion gate below; the message a hook blocks with is shown to the user and handed back to the model once.

### Added

- **Tool-produced images reach the model as image blocks.** MCP `image` content was flattened by `model_dump_json()` into the tool result text, so a Playwright screenshot became ~900 tokens of base64 the model cannot see. `McpClientManager.call_tool` now returns `McpToolOutput(text, images)` (capped at 4 images and 4 MB of base64 per call), `ToolResult`/`ToolResultBlock` carry the images to the engine, and `step_runner` moves them into the tool-results user message as sibling `ImageBlock`s — the one shape every adapter (Anthropic and OpenAI-compatible) already accepts. `is_model_multimodal` learned the `deepseek-v*` / `ds-v*` families, so DeepSeek v4 no longer detours through `image_to_text`, and microcompaction drops a screenshot together with the tool result it belongs to. Live check: a 49 KB screenshot was described correctly at 821 prompt tokens. See ADR-0015.
- `permissions/command_safety.py`: `classify_command()` returns a `ReadOnlyVerdict` (`read_only` / `mutating` / `unknown` plus a reason code and the triggering token); `is_read_only_command()` stays as a thin wrapper. Tools may expose `read_only_verdict()` / `read_only_reason()`, which the dispatcher forwards through `SecurityRequest` to the permission checker and into the `permission.decided` audit detail.
- `engine/verification_ledger.py` **and the completion gate it drives (ADR-0014).** The engine now tracks `edit_seq` / `opaque_seq` plus every classified verification run (`pytest`, `ruff`, `mypy`, `tsc`, `npm run build`, `make test`, …) with its return code and scope. A turn that ends with edits after the last workspace-wide green run gets one `synthetic` reminder instead of being reported as plain `completed`; the same reminder covers a blocked `stop` hook and leftover `git worktree` / `git stash` entries (`engine/session_hygiene.py`). Status is also appended to edit and verification tool results, because a tool result is the only channel the model reliably reads back. New setting: `verification.{enabled,nudge_limit,require_full_suite,hygiene_check}` (`nudge_limit=0` keeps the ledger but drops the reminder).
- Session memory now separates `## Verification` (last green full run + whether it is still valid) and `## Open Items` (unchecked checklist entries) from `## Explored`. The old heading called every inspected file and every executed command "Verified Work", which made a hand-off claim a verification that never happened.
- `api/transport.py`: one streaming-retry core shared by the Anthropic, OpenAI-compatible and Codex adapters. It never replays a stream that already emitted events (previously a mid-stream failure re-sent every delta and billed the prompt twice), retries structurally (`APIConnectionError`, transport errors, 408/409/425/429/5xx, `__cause__` chains) instead of by exception class, and reports the delay once through `RetryNotice`.
- `api/finish_reason.py`: normalized `FinishReason`, emitted by all adapters as `ApiMessageCompleteEvent.finish_reason`. `max_tokens` truncation now surfaces a status warning and is recorded in the `assistant.message` event instead of being persisted as a finished answer.
- `api/errors.py`: typed error taxonomy (`RateLimitFailure`, `OverloadFailure`, `ConnectionFailure`, `ContextLengthFailure`, `CompletionTokenLimitFailure`, …) plus `classify_api_error()`. The engine's prompt-too-long / max_tokens sniffing now delegates to it instead of keeping a private copy.

### Changed

- **Turn endings are now gated (ADR-0014).** A turn whose code edits have not been re-verified gets one reminder and one extra model step before it can end; `verification.nudge_limit = 0` restores the old behaviour while keeping the ledger. The system prompt gained a `# Finishing work` section that states the same contract ("done" means verified, exploration is not verification, leave the workspace as you found it).
- **ADR-0010 dependency direction and ports landed.** Conversation messages, usage, stream events, and event contracts moved to `openharness.domain`; the engine no longer imports `services` (and vice versa). Cross-layer seams (`EventLogPort`, `SessionAppendPort`, `MemoryPort`, `CompactPort`, `AgentRunPort`, `CronPort`, `LspPort`, `CodexSubagentPort`) live in `runtime/seams` and are injected by the runtime; `runtime.seams` no longer imports services. Final upward-edge check: `api→engine`, `engine→services`, `tools→services`, `tools→coordinator/swarm`, `runtime→engine`, `runtime→services`, and `channels→engine` are all 0; `services→engine` is limited to three composition imports in `services/assembly.py`.
- **Runtime assembly moved to a composition root.** `build_runtime` / `RuntimeBundle` / start-close and the API-client resolver live in `services/assembly.py`; the command registry is supplied by `openharness/assembly.py`, so `services` never imports `commands`. `ui/runtime.py` is a thin re-export.
- **Message SoT and cache-stability gates.** Sessions commit messages from the event-log projection (not the mutable working list), replay applies the same dangling-tool sanitization as resume, and `tests/test_engine/test_message_sot.py` compares live/replay `_message_wire_payload` hashes. Snapshots are now a fallback: resume prefers `events.jsonl`.
- **Large-module splits.** `swarm/permission_sync.py`, `config/settings.py`, `channels/impl/feishu.py`, `ui/runtime.py`, and `ohmo/gateway/runtime.py` were split into focused modules. The 54KB `file_size_limits` exemption is gone; large-file tracking is zero.
- `TurnExecutor` and `StepRunner` take a typed `QueryContext` instead of `Any`; `QueryEngine` resolves coordinator context through an injected provider instead of importing the `coordinator` package, removing the engine→feature dependency.
- `mypy` core paths now cover all of `src/openharness/api` and `src/openharness/engine` (0 errors); the global baseline dropped from 541 to 533.
- Chat-channel SDKs (`slack-sdk`, `python-telegram-bot`, `lark-oapi`, `qq-botpy`) moved to the `channels` extra; the unused `discord.py` dependency was dropped. A plain CLI install no longer pulls four chat SDKs, and a missing extra produces an actionable warning.


- Prompt-cache observability and stability. OpenAI-compatible usage now reads DeepSeek's `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens` (and keeps `stream_options.include_usage` for tool-using requests instead of dropping it for every provider). `UsageSnapshot` exposes hit/miss counters, `/usage` and the status bar report overall and hot-request hit rates plus cold starts, and a per-session `CacheDiagnostics` fold classifies each request as cold start, system drift, tool drift, history append, or compaction rewrite. `oh --dry-run` prompt diagnostics now include per-section SHA-1 hashes.
- Cwd, date and git branch moved out of the cached system-prompt prefix into a trailing `environment_live` section. Permission mode, fast mode, effort/passes, and glob-scoped Cursor rules also moved to the tail, so switching plan mode, `/fast`, `/effort`, `@file` context, or a git branch no longer invalidates the stable prefix. `set_system_prompt()` now refreshes the cacheable prefix alongside the text.
- The runtime now freezes the session-stable system prompt (base, personality, model profile, tool discovery, skills, delegation, always-apply project rules, local rules) and attaches all per-turn context (permission mode, fast mode, effort/passes, memory, relevant memories, scoped rules, issue/PR/repo context, cwd/date/branch) to the latest user message at request time. The context is never persisted in the session history, so `@file` turns, plan-mode switches, and `/effort` no longer change the system+tools prefix. The first headless turn waits briefly (`cache_warmup_wait_seconds`, default 2s) for the background warmup instead of racing it.
- Tool results are now shrunk before they enter the model-visible history when they would push the next request past a configurable hit-rate budget (`OPENHARNESS_CACHE_TARGET_HIT_RATE`, default 0.95). The full output is still written to `tool_artifacts/`; only the inline preview is shortened. This directly limits the miss caused by a large `cat`/log/test-output result. `OPENHARNESS_CACHE_BUDGET=0` disables it.
- Compaction now has a cooldown (`OPENHARNESS_COMPACT_COOLDOWN_SECONDS`, default 180s) so a recent history rewrite does not immediately trigger another one; an emergency compaction is still allowed near the hard limit. DeepSeek models use a 128k context window instead of the generic 200k default, so auto-compact fires with headroom instead of falling back to a reactive prompt-too-long compaction.
- Cache fingerprints now hash only the provider-visible message shape (`result_metadata`, `provider_item_id`, `visibility`, and `source_path` are excluded), so local bookkeeping updates no longer produce false `history_rewrite` classifications.
- Deferred tools activated by `tool_search` are appended to the wire schema instead of being inserted at their registration position, preserving the cached tool prefix for the rest of the session.
- Optional prompt-cache warmup (`CacheWarmup`): a background, one-token, non-streaming request at session startup for implicit-cache providers (`deepseek`, `openai`), deduped per process/prefix/TTL. Works through both the OpenAI-compatible client and the Anthropic-compatible client (DeepSeek's `/anthropic` gateway), where a one-token dummy user message is placed after the system+tools prefix. Enabled automatically for those providers; set `OPENHARNESS_CACHE_WARMUP=0` to disable or `OPENHARNESS_CACHE_WARMUP=1` to force it for other compatible providers. Warmup usage is accounted separately and never counted in the user-visible hit rate.
- Large user pastes are offloaded before they enter the prompt. A pure-text user message at or above `large_paste_threshold_chars` (default 24,000) is written to `<data>/user_pastes/` and replaced by a marker with the first/last preview plus the artifact path, so a 50k-character document no longer costs a full prompt-cache miss on the first request and is never re-sent on later turns. The model reads the exact text on demand with `read_file` (offset/limit) or `grep`. Enabled by default; `OPENHARNESS_OFFLOAD_LARGE_PASTES=0` disables it, and `OPENHARNESS_LARGE_PASTE_THRESHOLD_CHARS` / `OPENHARNESS_LARGE_PASTE_PREVIEW_CHARS` tune the cut-off. Images, tool results and assistant messages are never transformed, and an unwritable data directory falls back to sending the original text.
- Optional cache keepalive (`CacheKeepalive`): when `OPENHARNESS_CACHE_REFRESH=1`, the engine re-warms the session prefix after `cache_refresh_idle_seconds` (default 600s) without a model request, covering long tool calls and idle gaps that can outlive the provider's implicit cache. The refresh is a forced one-token warmup (bypassing the warmup TTL dedupe), is skipped while a real request is in flight, and is cancelled when the runtime closes. It is off by default because the provider TTL is not public; `/usage` reports refreshes, busy skips, and failures separately from the hit rate.
- Standalone bundle: `python scripts/build_bundle.py` builds `dist/shim/` with a single `shim.exe` (Python runtime + application + bundled skills + prebuilt React terminal) plus an `ohmo.cmd`/`ohmo` launcher. PyInstaller excludes tests, docs, benchmarks, assets, plugins, the autopilot dashboard, and repository-only tooling; users only need Node.js >= 18 on PATH.
- The React terminal frontend now builds to a single `frontend/terminal/dist/index.js` via esbuild (`npm run build`), so packaged installs no longer run `npm install` on first launch.

- `ohmo gateway logs [-n N] [-f]`: prints the gateway log file (`~/.ohmo/logs/gateway.log`) and can follow it like `tail -f`. `gateway start` and `gateway restart` now print the log path, since the daemon intentionally runs with `--no-console-log` and its stdout/stderr go to that file.
- Benchmarks: added `benchmarks/` with a deterministic harness-conformance suite (`--suite core`, CI-friendly via `tests/test_benchmarks`), a real-model capability smoke suite (`--suite real`), JSON reports with harness/model metadata, Wilson 95% confidence intervals, and baseline comparison. An official HumanEval adapter (`--suite humaneval`) runs agent-written `solution.py` through OpenAI's `check_correctness`; on Windows it invokes the same official grader through WSL because the official runner depends on `signal.setitimer`. Install the optional extra with `uv sync --extra benchmark`. SWE-bench/Terminal-Bench adapters are not included yet because their official harnesses require Docker images that this environment cannot reach.
- Desktop completion notifications: when an agent turn finishes, Shim can raise a Windows notification-center balloon (PowerShell `NotifyIcon`), a macOS banner (`osascript`), or a Linux `notify-send` notification. The body is the start of the final assistant message plus elapsed seconds. `/notify [show|on|off|test]` controls it, and `settings.notifications` exposes `enabled`, `on_turn_complete`, and `min_duration_seconds`; failures are silent so notifications can never break a turn.
- Renamed the product to **Shim** (formerly OpenHarness). Added the `shim` console entry point; `oh`, `openh`, `openharness`, the Python package name, `OPENHARNESS_*` variables, and `~/.openharness` remain compatible. CLI help, `--version`, terminal title, README branding, and the base prompt identity now use Shim.
- Personality/persona layer: built-in `shim`, `concise`, `mentor`, and `neutral` presets plus custom text. `/personality [show|list|set NAME|custom TEXT|off]` and `--personality` control it; the default is Shim, and the persona is injected as a cacheable system-prompt section. Disabling it restores a neutral assistant voice.
- Reasoning effort/thinking now reaches providers: Anthropic requests enable extended thinking with effort-scaled budgets (`low` 1024 → `xhigh` 16384) for Claude 3.7+/4+ and reasoning-named models on Anthropic-compatible proxies; `/effort off` sends an explicit disabled marker so reasoning-model proxies stop thinking. OpenAI reasoning models receive `reasoning_effort` (`gpt-5`/`o1`/`o3`/`o4`), Codex keeps its `reasoning.effort`, and `/thinking on|off|toggle` provides a direct toggle. On proxies that ignore the budget, on/off still works even when low/medium/high do not change depth.
- `/loop` slash command: schedules a recurring agent prompt through the existing cron scheduler. `"/loop 5m check the build"` creates a `shim_turn` cron job that runs `python -m openharness --print ...` with the current model, effort, personality, permission mode, and tool profile. Supports `/loop status`, `/loop list`, and `/loop stop [NAME|all]`; the scheduler auto-starts if needed, and each run's output lands in `oh cron history` / `oh cron logs` rather than the current conversation.
- Tool visibility profiles: the default `core` profile sends 16 everyday tools (~2.2k schema tokens) instead of all 39 (~6.6k). Deferred built-ins (images, notebooks, LSP, cron/remote, background tasks, teams, worktrees, config/brief/sleep) are hidden until `tool_search` matches them; matches are enabled for subsequent turns. Plugin/MCP tools stay visible. Configure with `/tools [show|profile core|full|enable NAME]`, `--tool-profile core|full`, or `settings.tool_profile`; a Tool Discovery prompt section explains the flow.
- `/usage` now breaks the estimated context into system prompt, tool schemas, and conversation tokens, so the fixed per-request overhead is visible. The TUI's cumulative `tokens:` counter and conversation-only `ctx:` estimate are distinct from the provider's per-request input count.
- `/thinking show` reports whether the last assistant turn actually contained thinking/reasoning blocks (count and characters), and `/thinking probe [on|off]` sends a minimal live request to the active provider and reports the returned blocks and output tokens. This distinguishes "configured" from "actually thinking" without inspecting logs.
- Plugin variables and tokens: `plugin.json` can declare a `variables` map (`description`, `secret`, `required`, `env`, `default`). Users manage them with `oh plugin config show|set|unset <plugin> [KEY]`; `set` prompts without echo. Values use the system keyring when available and otherwise the mode-600 credentials file, with environment variables taking precedence. `oh plugin list` reports missing required variables, and plugin tools resolve them through `openharness.plugins.config.get_plugin_variable`.
- SSH connection reuse: new `ssh-remote` plugin contributes an `ssh_exec` tool with OpenSSH `ControlMaster=auto` and `ControlPersist`. On Windows it routes through WSL's Linux OpenSSH, because native Windows OpenSSH rejects ControlMaster (`getsockname failed`) and Git Bash's MSYS build resets every multiplexed session. Verified against `root@example.com:22`: first command ~9.5 s cold (~2.1 s warm), reused command 0.08–0.15 s.
- Tavily search plugin (`plugins/tavily-search`): contributes a read-only `tavily_search` tool through the existing plugin tool-loader. It declares `TAVILY_API_KEY` as a required secret, configurable with `oh plugin config set tavily-search TAVILY_API_KEY` or the `TAVILY_API_KEY` / `TVLY_API_KEY` / `OPENHARNESS_TAVILY_API_KEY` environment variables, and supports search depth, topic, domains, recency, and an optional synthesized answer. Install with `oh plugin install ./plugins/tavily-search`.
- React TUI: terminal writes are wrapped in DEC synchronized-output markers (mode 2026), so Ink's erase+redraw for Up/Down history, transcript scrolling, and other key presses is applied as one atomic paint instead of a visible full-screen flash. Terminals without mode 2026 ignore the markers. The dynamic frame also leaves three rows of headroom below the terminal height, so Ink's trailing newline no longer scrolls the viewport on every render (the remaining Windows Terminal flash source).
- React TUI: the terminal tab/window title now follows OH state via OSC 0 (`○ idle`, `● busy`, `◆ waiting for input`, `◌ connecting`), includes the model and queued-message count, uses `oh`/`ohmo` as the app name, and is reset on exit. Disabled automatically when stdout is not a TTY.
- React TUI: type while the agent is running and queue messages; queued turns send automatically when the current turn finishes. The prompt keeps its `>` cursor and gains a "type to queue" placeholder instead of looking disabled, each queued message is listed by content under the prompt (`↳`), and `↑` pulls the latest one back into the editor (images included) before the turn ends. The `/` command picker, ↑/↓ history, and `ctrl+v` image attach now also work mid-turn; submitting from the picker queues the command instead of racing the running turn.
- React TUI: `ctrl+r` reverse history search and `?` keyboard-shortcut help overlay.
- React TUI: oversized command output such as `/context` (which prints the whole runtime system prompt) no longer floods the conversation and leaves the live frame overwriting its tail. Long system/log output is clamped to the viewport with a `ctrl+o full transcript` hint, and the full text opens in a scrollable **Command output** view that closes with `esc`, `q`, or `ctrl+o` (↑/↓, `j`/`k`, pgup/pgdn, `g`/`G` scroll).
- React TUI: status bar now shows real context usage, queued-message count, and elapsed turn time.
- React TUI: option-based `ask_user_question` prompts now end with an **Other (type your own answer)** entry. Selecting it turns that row into a free-text input, so a predefined option list never blocks a custom answer.
- React TUI: `@` file mentions with fuzzy completion, `!` direct shell execution, `ctrl+o` tool output expand/collapse, `ctrl+y` copy, turn-completion bell, command descriptions/usage hints, and a scrollable diff review modal.
- Prompt/tool guidance now actively encourages batching independent reads/searches/bash calls and proactively spawning subagents for parallel research, implementation, and verification. The `agent` tool defaults to the `worker` profile and tells the model how to collect results.
- Prompt management: composable prompt sections with ordering, per-section and total budgets, cacheable metadata, provider-specific profiles, capability-aware delegation, and section diagnostics in `oh --dry-run`.
- Project instructions now load `CLAUDE.md`, `AGENTS.md`, `.claude/rules/*.md`, `.cursor/rules/*.mdc`, and `.cursorrules`; `.mdc` frontmatter is parsed for description/glob scope. Subagent prompts are OpenHarness-branded instead of Claude Code-branded.
- Prompt caching: Anthropic requests send the contiguous cacheable prompt prefix as a `cache_control: ephemeral` system block when it is large enough. Prompt version and cacheable character counts are exposed in `oh --dry-run`.
- Cursor glob rules with `alwaysApply: false` now apply only when a turn's active files match their globs. Active files come from `@mentions`, path-like prompt tokens, `read_file_state`, `active_artifacts`, and the recent work log; the prompt is rebuilt on file-context turns.

- The package version now comes from `src/openharness/version.py` (Hatch dynamic version) instead of being duplicated in `pyproject.toml`, `ohmo`, and the CLI; `ohmo` reports the same version.
- Removed historical repository artifacts (`TODO.md`, `RELEASE_NOTES_v0.1.8.md`, `RELEASE_NOTES_v0.1.9.md`) from the release surface; `CHANGELOG.md` remains the source of release history. The source distribution now includes only runtime code, bundled skills, the prebuilt frontend, and the standard project files.
- The plan checklist is now session-scoped instead of the repository's global `TODO.md`. `todo_write` defaults to `plan-<session>.md` under the project's session directory in every mode, and marks an item done in the session plan whenever that item lives there — including after exiting plan mode, which previously appended the update to `TODO.md` and left the sidebar checkbox stale. Plan mode ignores a requested path entirely, the sidebar shows only the session file, and the path is persisted so `--resume` reloads the plan. Item matching tolerates case/whitespace drift when flipping the checkbox, and the plan prompt now requires `todo_write(item=<exact text>, checked=true)` immediately after each completed item. Explicit `path` writes still target project files.
- The plan-mode allowlist now matches "read-only" instead of "only a tiny set of built-ins": `Explore`/`Plan` subagent calls are treated as read-only delegation, `enter_plan_mode` is a no-op without a confirmation prompt when already in plan mode, MCP tools annotated `readOnlyHint` stay available, and the bash classifier accepts `2>&1` / `>/dev/null`-style safe redirections plus `tree`, `jq`, `du`, `df`, `fd`, and `fdfind` (with their file-writing/exec flags still rejected). The block reason now states what remains available and how to exit.
- Plan-mode switching now works end to end. Auto mode tells the model when to call `enter_plan_mode` (planning/design without edits) and how `exit_plan_mode` resumes implementation, and `/plan off` now returns to Auto to match the tool instead of silently dropping to Default. ### Fixed

- `ohmo --continue` / `--resume <id>` now actually restore the saved session in the default TUI. The launcher resolved the snapshot and then dropped it: only `--backend-only` restored messages, while the React frontend spawned a backend without `--continue`, silently starting a fresh session. The launcher now validates the snapshot (failing fast with a clear message when none exists) and forwards `--continue` / `--resume` in the backend command; backend and `--print` modes pass messages plus persisted work state, and `/resume` restores read-file state, work log, verified work and focus metadata, and restored messages are replayed into the TUI transcript so a continued session no longer opens blank. Restored metadata is filtered through `resumable_tool_metadata`, so a snapshot's stale `permission_mode` can no longer overwrite the live mode.
- React TUI: Markdown tables wider than the terminal are capped to the visible width and their cell contents wrap inside the borders (CJK/wide-character aware). Previously Ink wrapped the row `<Text>` at the terminal edge, splitting borders across lines and turning large tabular answers into unreadable output; pathologically wide column sets now fall back to a `column: value` record layout.
- Bash execution no longer hangs before the first command when the backend process was started by the Node TUI. The Windows bash-availability probe used `bash -lc "exit 0"` with captured pipes; a slow login profile could trip the 5 s timeout, and `subprocess.run()` then waits in an unbounded `communicate()` for pipe EOF from a profile-spawned grandchild, freezing the event loop indefinitely. The probe now runs the `exit 0` builtin with `-c` and sends all three streams to `DEVNULL`.
- Bash tool drains stdout while the command runs instead of waiting for exit and reading afterwards. Commands whose output exceeded the OS pipe buffer (for example an untruncated `git diff`) used to block on write while the tool waited for exit, appearing as a hang until the timeout. A terminal grandchild that keeps the pipe open after the shell is killed can no longer stall completion either.
- Default permission mode no longer asks for confirmation before read-only bash commands. The bash tool now classifies its command with a conservative allowlist: simple inspectors (`ls`, `cat`, `grep`, `head`, …) and read-only git subcommands (`status`, `log`, `diff`, `show`, `branch -a`, `config --get`, …) run immediately, including in `&&` / `||` / pipe chains. Redirections, command or variable substitution, background jobs, mutating git subcommands and flags, unrecognised commands, and any path inside a credential tree (`~/.ssh`, `~/.aws`, `~/.openharness`, …) still require approval.
- Windows shell resolution no longer selects the WSL `bash.exe` launcher (`%LOCALAPPDATA%\Microsoft\WindowsApps\bash.exe` or `System32\bash.exe`). It passes liveness probes but cannot see a Windows `cwd`, has no Windows executables on `PATH`, and re-splits argv, so every spawned command failed or mis-quoted. Resolution now rejects it by identity and falls back to a real MSYS/Git bash, then PowerShell.
- Hook `$ARGUMENTS` is no longer spliced into the command text. `shlex.quote` only holds for a POSIX shell that does not re-split argv; the same string handed to PowerShell or a WSL bash launcher still executed `$(...)`. Command hooks now substitute a reference to `OPENHARNESS_HOOK_PAYLOAD`, which the shell expands itself, using the dialect of the shell that will actually run the command.
- Background agent tasks spawn with `sys.executable` instead of a bare `python`, so they no longer exit 127 on Windows or inside a virtualenv.
- Windows subagent stop-hook test now invokes the current interpreter in POSIX form so Git Bash can execute it reliably.
- `oh` and `ohmo` now reconfigure stdout/stderr for UTF-8 on Windows (code page 65001 when a console is attached, replacement characters as a fallback), so model output containing emoji or other non-GBK characters no longer raises `UnicodeEncodeError`.
- External command output (git, gh, provider CLIs, worktree helpers) is decoded as UTF-8 with replacement instead of the Windows locale code page. CJK commit messages and other non-ASCII output no longer trigger `UnicodeDecodeError` in the subprocess reader thread or silently drop output.
- Redirected stdin is decoded as UTF-8, so piping CJK prompts into `oh -p -` behaves the same as on POSIX.
- `write_file`, `edit_file`, `todo_write`, and notebook edits no longer translate `\n` to `os.linesep` on Windows: new files use LF and existing CRLF files stay CRLF.
- `ohmo gateway` process discovery falls back to the PowerShell CIM provider when `wmic` is absent (recent Windows 11 builds), so background gateways remain discoverable.
- The Windows bash availability probe is cached per executable; shell resolution no longer pays a ~300 ms `bash -lc "exit 0"` probe on every command.
- Timed-out `bash` commands now terminate the whole Windows process tree via `taskkill /T` instead of only the shell, so child processes such as `npm` and `pytest` no longer survive a timeout.
- Windows shutdown no longer prints `Exception in callback _ProactorBasePipeTransport._call_connection_lost`: CLI/ohmo/cron entry points use a shared `run_async` wrapper that filters the benign WinError 10054 teardown raceless and forwards all other loop errors, and runtime teardown yields once so transport close callbacks settle before the loop closes.
- React TUI: `ctrl+o` now mirrors Claude Code's transcript viewer. It switches the conversation area to a bounded transcript panel with complete (untruncated) tool output, scrolls with `↑/↓`, `j/k`, `pgup/pgdn`, `ctrl+u/d`, and `g/G`, and closes with `ctrl+o`, `ctrl+c`, `q`, or `esc`. The app shell stays mounted so Ink can redraw reliably on Windows (the previous viewport-filling replacement could leave the transcript on screen and make the second toggle look broken). The prompt becomes read-only while the viewer is open, overlays are hidden, collapsed tool blocks show `(ctrl+o to expand)`, and `ctrl+o` no longer inserts an `o` into the prompt because the text input ignores all `ctrl` chords handled by the app.
